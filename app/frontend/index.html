Why does each model need its own packages?

Different model families use different inference libraries. Kokoro, VoxCPM2, Bark, Voxtral, Spark-TTS, OmniVoice, and Fish S2 Pro use mlx-audio, while F5-TTS uses its own flow-matching engine and VoCoS vocoder. The catalog mixes models from different ecosystems so you can pick the right tool for each task — but each library has to be importable for that model's engine to run.

Normally this is a one-time install. Re-run Reinstall Generation after a Reset, on a new machine, when release notes request it, or when this panel reports an incompatible package. Restart the server afterward.

The "Install Generation" script bundles all the libraries together for simplicity. If you only ever plan to use one engine (say, Kokoro), the extra packages still install but they're idle — they don't slow anything down.

Import existing weights

Symlinks an existing HF-cache-style folder into this server's HF cache, so you don't re-download models you already have on disk. No copying.

What's the difference between Link and Move?

  • Link creates a symlink under our HF cache pointing at the source. Instant, zero copy, but if you later uninstall the source app, the link breaks. Best when you want to keep both Pinokio apps installed and share the same on-disk cache.
  • Move physically relocates the folder into our HF cache. On the same disk it's an instant rename (no copy), across disks it falls back to copy+delete. Afterward, the source is gone — you can safely delete the old launcher entirely. Best for migrating from another TTS app or cache.

📚 Tips for great cloning reference clips
  • Length: 5–15 seconds. Shorter = less voice character captured. Longer than 20s doesn't help any engine.
  • Quality: clean room, no background music, no echo. Phone recordings in a quiet space work fine.
  • Content: a few full sentences that vary in pitch. Reading a pangram (e.g. "The quick brown fox jumps over the lazy dog. Pack my box with five dozen liquor jugs.") gives engines a broad phoneme set.
  • Transcripts: F5-TTS specifically needs an exact transcript of the reference clip for alignment. Other engines don't require it. Toggle "Add transcript" in the upload dialog if you'll use F5.
  • Ethics: only clone voices you have permission to use. Voice cloning of public figures, ex-partners, etc. without consent is illegal in many jurisdictions and harmful even where it isn't.

Hugging Face token

Status: ✓ Saved Not set ()

Why bother setting one?

A Hugging Face token is your personal pass to the HF model hub. Without one, you're an anonymous downloader — which means:

  • Lower rate limits. HF throttles anonymous traffic far more aggressively. Big downloads stall or hit caps.
  • Slower CDN tier. Authenticated requests get priority routing to closer edge servers.
  • No access to private or future gated voice models. A token lets Voice Studio download repositories your Hugging Face account is authorized to use.
  • No access to your own private models. If you've trained or uploaded private LoRAs/checkpoints, the token gives you access here too.

The token is stored locally in app/backend/settings.json. It never leaves your Mac except as an Authorization header sent directly to huggingface.co during downloads. We never log it.

How to get one (30 seconds)
  1. Go to huggingface.co/settings/tokens (sign up free if you don't have an account)
  2. Click Create new token
  3. Token type: Read is enough. Don't pick "Write" or "Fine-grained" unless you know you need them.
  4. Name it something memorable (e.g. voicestudio-mac)
  5. Copy the token (starts with hf_…) and paste it below

If a voice repository is gated, visit its Hugging Face page once and accept its license before downloading. The current built-in catalog is public, so the token is mainly useful for higher rate limits and private repositories.

Bound port

Hardcoded in start.js so it survives every restart. If you ever want to change it, edit the --port arg there and Stop → Start.

How does direct API access work here?

Our server is configured to bind on 0.0.0.0 at a fixed port , which means it listens on every network interface (loopback + LAN + Tailscale). Any device that can reach this Mac on that port can call the API directly — no Pinokio proxy needed, no port-rotation surprises.

That's a deliberate trade-off from the "127.0.0.1-only secure default" you might see in other apps:

  • Pro: stable URL, lower latency, full /docs Swagger access from any device, easy scripting.
  • Con: the API has no built-in authentication right now, so anything on the network you bind to can call it. On a personal Tailscale tailnet (only your own devices) that's fine — but don't expose port to the public internet without adding an auth layer first.

To revert to the "secure default" (loopback only), edit start.js and change --host 0.0.0.0 back to --host 127.0.0.1. Then access becomes Pinokio-UI-only again.

Are these addresses stable?
  • App port (): Yes — pinned in start.js. We hardcoded port so it survives restarts and scripts can reliably target it. If it ever clashes with another app, change the number in start.js.
  • Pinokio UI port (42000): Yes — stable. Pinokio's hardcoded default. Use this as your remote-access entry point.
  • LAN IP (192.168.x.y / 10.x.x.x): Usually yes. Assigned by your router via DHCP, typically stable for days or weeks. For permanence, set a DHCP reservation on your router.
  • Tailscale IP (100.x.x.x): Yes — permanent. Assigned by Tailscale per node, stable for the life of that machine in your tailnet. Best choice for stable remote access.
  • Share proxy port: You control it. Set PINOKIO_SHARE_LOCAL_PORT in ENVIRONMENT for a fixed value, leave it blank to let Pinokio pick random per session.
